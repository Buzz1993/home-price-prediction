# UI Documentation

Version: 1.0

---

# UI Overview

The existing Streamlit application is the reference implementation for the EstateMind Copilot.

Reuse its workflows, backend integrations, and user experience.

The Next.js frontend should modernize the user interface while preserving the existing functionality.

The frontend is responsible only for presenting data returned by the backend.

Do not redesign workflows or move business logic to the frontend.

---

# Design Principles

- Clean
- Modern
- Responsive
- Minimal
- Reusable Components
- Consistent Layout
- Fast Navigation

Business logic must remain in the backend.

# UI Philosophy

The UI should feel like a premium modern real estate platform.

### Color Theme

Use the provided dashboard design as the primary visual reference.

Use

- White background
- Green accent colors
- Soft gray cards
- Rounded corners
- Modern spacing
- Clean typography

Keep the color palette and styling consistent across the entire application while preserving the AI-first workflow.

Priorities:

- Simple
- Professional
- Responsive
- Easy to navigate
- Minimal distractions

Avoid unnecessary animations or decorative components.

**Purpose**

### Property Card

Each search result is displayed as a reusable Property Card.

**Components**

- Property ID
- BHK
- Bookmark
- Primary Image
- Project Name
- Locality
- Bedrooms
- Bathrooms
- Parking
- Balcony
- Area
- Cost per Sqft
- Price
- Investment Score
- Read More

**Behavior**

- Clicking the card opens Property Details.
- Bookmark saves/removes the property.
- Investment Score is provided by the backend.

**API**

POST /search

**Navigation**

Search → Property Details

### Property Map

Display search results on an interactive map.

**Components**

- Interactive Map
- Property Markers
- Price Labels
- Selected Property Highlight
- Map Zoom Controls

**Behavior**

Default View

- Display all available properties returned by the backend.
- Show only the formatted price on each marker.

Search Results

- Display only the returned search results.
- Each marker displays:
  - Primary Image
  - Price
  - Cost per Sqft
  - Area
  - BHK

- Clicking a marker opens Property Details.
- Clicking the property image opens the Image Gallery.
- Selecting a Property Card highlights the corresponding map marker.
- Selecting a map marker highlights the corresponding Property Card.
- The map automatically fits all visible properties.

# UI Guidelines

- Follow the existing Streamlit workflows.
- Keep page navigation consistent.
- Use reusable components.
- Keep layouts responsive.
- Support desktop, tablet, and mobile devices.
- Show loading, empty, success, and error states.
- Do not implement backend business logic in the frontend.
- Improve visual design without changing user workflows.
- Preserve the existing chat-first workflow.
- Preserve the evaluation tray workflow.
- Use backend `image_urls` for all property images.
- Do not use placeholder images when `image_urls` are available.
- Open property images inside a reusable fullscreen gallery.
- Reuse the same gallery component on both Property Cards and Property Details.
- Selecting a Property Card and its corresponding map marker should keep both views synchronized.
- The map should automatically adjust its viewport to include all currently displayed properties.
- Use backend latitude and longitude to render property locations.
- When no search is active, display all properties on the map using price-only markers.
- When search results are available, display only the returned properties on the map.
- Rich property markers should display:
  - Primary Image
  - Price
  - Cost per Sqft
  - Area
  - BHK
- Format prices consistently:
  - 2.0 → 2 Cr
  - 1.25 → 1.25 Cr
  - 0.50 → 50 Lakh
  - 0.75 → 75 Lakh
- Use the provided dashboard design as the primary visual reference.
- Maintain a consistent green and white color palette across all pages.
- Property Details should automatically organize all backend property metadata into logical sections.
